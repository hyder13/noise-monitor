# 低頻噪音記錄儀

手機網頁版噪音事件記錄器。針對**住宅低頻噪音與衝擊音的舉證**設計，不是一般的分貝計。

單一檔案 `index.html`，無建置流程、無外部相依（字型走 Google Fonts，離線時自動退回系統字型）。

---

## 為什麼不用現成的分貝 App

一般噪音 App 只給 dB(A)。A 加權的設計目的是模仿人耳對低頻不敏感的特性，在 50 Hz 會把能量壓掉將近 30 dB。

水錘、管路共振、加壓馬達的能量都集中在 20–150 Hz。用 dB(A) 測會得到「才 45 分貝，沒超標」——**這份數據反而會被用來證明你沒事**。

本工具同時記錄三軌，並把差值本身當成主要指標。

| 指標 | 用途 |
|---|---|
| **dB(Z)** | 線性，不做任何頻率修正 |
| **dB(C)** | 保留低頻 |
| **dB(A)** | 模仿人耳，法規使用 |
| **C − A** | **低頻主導指標**。≥15 dB 即判定為低頻主導（NSW 噪音政策門檻；Hessler 2004 採 20 dB） |
| **峰值因數** | 瞬時峰值與有效值之比。區分「敲擊型」與「持續嗡鳴型」的關鍵 |
| **1/3 八音度窄峰** | 依 NSW tonality 準則：25–125 Hz 需高出鄰帶 15 dB、160–400 Hz 需 8 dB |

**未校準也有效**：C−A 差值、窄峰位置、峰值因數、事件時間分布都不受校準偏移量影響（同時量測、偏移量互相抵消）。只有絕對音壓值需要校準。

## 功能

- **三軌即時量測** — Z / C / A 同步，FFT 8192 點，即時頻譜 0–500 Hz
- **自動事件偵測** — 門檻相對於滾動 L90 背景底噪，白天吵、深夜靜都能自動適應
- **衝擊音偵測** — 獨立的瞬態偵測器。逐取樣追蹤真實峰值，抓得到只有 20–50 毫秒、撐不到持續時間門檻的「趴」一聲
- **事件自動分類** — 低頻共振 / 衝擊音 / 手動標記
- **窄峰判定** — 1/3 八音度分析，自動標示共振頻率，並對 60 Hz 倍頻（台灣電網；冰箱、加壓馬達）提出假陽性警告
- **敲擊指紋比對** — 敲擊可疑結構存成參考頻譜，之後每個事件自動比對形狀相似度，用於溯源
- **前置緩衝錄音** — 事發前 4 秒 + 全程 + 事後 2 秒，16 kHz 單聲道 WAV
- **情境標記** — 開關冷氣、開關水閥等操作標在時間軸上，用於做對照實驗
- **趨勢圖表** — 時段分布、音量趨勢、主頻分布、平均事件頻譜
- **ZIP 打包匯出** — 報告 HTML + CSV + JSON + 全部 WAV，可整包交付
- **溝通報告** — 自動判讀，附可援引的建築技術規則條號與求償流程

## 手機上怎麼跑

需要 **HTTPS**（瀏覽器只在安全來源開放麥克風，`file://` 不行）。

### GitHub Pages

```bash
git remote add origin https://github.com/<你的帳號>/noise-monitor.git
git push -u origin main
```

到 repo 的 Settings → Pages → Source 選 `main` / `(root)` → 儲存。約一分鐘後在
`https://<你的帳號>.github.io/noise-monitor/` 開啟。

手機 Chrome 開啟後，選單 →「加到主畫面」，就有一個獨立圖示。

### 本機測試

```bash
python -m http.server 8000
```

電腦上開 `http://localhost:8000`（localhost 視為安全來源）。手機連區網 IP 會因為不是 HTTPS 而拿不到麥克風。

## 量測前務必確認

**自動增益（AGC）必須關閉。** 程式已在 `getUserMedia` 要求關閉，但 Android 常常忽略，因此另外用 `track.getSettings()` 回讀實際生效的設定，並顯示在「設定 → 分貝校準」下方。

AGC 若仍開著，系統會持續調整麥克風靈敏度：大聲被壓低、安靜被抬高，校準偏移量失去意義，**不同時間點的數據無法互相比較**。此時 C−A 與窄峰仍可用，但必須在報告中註明。

**校準偏移量**預設 115 dB。這個值等於麥克風的滿刻度音壓，手機多落在 110–125。有分貝計的話兩台並排對同一個穩定聲源，拖動滑桿讓 dB(A) 讀數一致即可。

**網頁版無法背景執行。** 瀏覽器一旦被系統休眠就停止收音。掛整晚必須插電並保持螢幕開啟（程式會自動請求 Wake Lock）。真正的背景監測要等打包成 App。

## 對照實驗設計

只有一支手機時，靠分時段對照與位置比較取代同步量測：

1. **關閉自家總水閥 30 分鐘** — 聲音仍在，代表不是自家管路
2. **請樓上在約定時間沖水** — 看事件是否跟著出現
3. **冰箱拔電 10 分鐘** — 排除 60 Hz 倍頻的假陽性
4. **開關冷氣前後各測一小時** — 木作熱脹冷縮的聲響與溫度變化率相關，不是與時間相關
5. **深夜最安靜時段測背景 L90** — 建立對照基準
6. **同一支手機在多個位置分次測** — 比較同類事件的音量，最響處最接近聲源

每段實驗都用情境標記按下起訖點。

### 關於方位

**單支手機測不出聲音方位，這是物理限制而非軟體限制。** 聲源定位需要兩個以上分開的麥克風計算到達時間差；Web Audio 只能取得系統混音後的單聲道，且手機麥克風間距約 15 公分，而 50 Hz 的波長是 6.8 公尺——基線比波長小兩個數量級。這也是為什麼重低音喇叭可以隨意擺放：低頻本來就缺乏方向感。

替代方法是**敲擊指紋比對**：每個結構被激發時只會在自己的固有頻率上響，那組頻率就是它的身分證。

## 資料儲存

全部存在手機瀏覽器本機（IndexedDB），不上傳任何地方。

- `events` — 事件記錄，含 140 段頻譜快照與 1/3 八音度頻帶值
- `samples` — 每秒聚合的 Leq（Z/C/A）與峰值頻率
- `audio` — WAV 音檔，約 32 KB/秒

設定、情境標記、敲擊指紋存在 `localStorage`。

清除瀏覽器資料會一併刪除，長時間記錄請定期用 ZIP 匯出備份。

## 已知限制

- 手機 MEMS 麥克風在約 30–80 Hz 以下有滾降，最低頻段會被低估
- 絕對音壓值未經聲學校準，不能直接用於判定是否符合法規管制標準
- 法規的低頻量測要求 IEC 61260 Class 1 濾波器，手機達不到
- 麥克風在約 90–100 dB 以上會削波飽和（介面會標成橘色警示）
- 本工具的定位是**篩選、鎖定時段、證明相關性與規律性**。正式認定仍需環保局檢測或技師公會鑑定
